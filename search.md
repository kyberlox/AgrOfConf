# Логика модуля подбора (module_search.py)

## Точка входа

**POST `/module_search/process_table_data`**

Принимает `product_id` и словарь `selected_params` (параметры, выбранные пользователем).

## Основной алгоритм

### 1. Подготовка данных

1. Загружает имя продукта и все параметры типа `Table` с привязкой к таблицам Excel
2. Формирует `tables_map`: `{table_name: [param1, param2, ...]}`
3. Определяет `formula_driven` — параметры, значения которых задаются формулой (давление, клапан)
4. Гарантирует наличие витрины данных (datamart) для продукта

### 2. Если пользователь ничего не выбрал

- Для каждого параметра берёт все уникальные значения из витрины
- Если витрина не отдала значения (например, «Тип среды») — запрашивает их напрямую из таблицы
- Если у параметра только одно значение — автоматически подставляет его в `response_value`
- Параметры, управляемые формулой, не подставляются автоматически

### 3. Если параметры выбраны

#### 3.1 Фильтрация мусорных параметров (смесь)

Если включён режим смеси и задан состав — характеристики среды (вязкость, плотность и т.п.) пересчитываются формулой. Их нельзя использовать как критерий табличного подбора, иначе возникает зацикливание. Такие параметры исключаются из `table_selected_params`.

#### 3.2 Подбор по каждой таблице

Для каждой таблицы вызывается `get_table_params_from_sql`:

1. Формирует SQL-запрос с WHERE-условиями на основе выбранных параметров
2. Параметры с типом `list` → условие `IN (...)`, scalar → `= :value`
3. Параметры, управляемые формулой, пропускаются (не используются как критерии)
4. SELECT возвращает `array_agg(DISTINCT column)` для каждого столбца + `COUNT(*) AS matched_rows`
5. Суммирует `matched_rows` по всем таблицам

#### 3.3 Поиск ошибок подбора

`find_search_errors_multi_table` — определяет, **какой именно параметр** привёл к невалидной комбинации:

1. Проверяет, что ВСЕ параметры таблицы вместе дают 0 строк
2. Если комбинация невалидна — добавляет параметры по одному в порядке `sort` (или с учётом `priority`)
3. Как только добавление параметра ломает подбор — он считается ошибочным
4. Для ошибочного параметра `get_available_values_for_error_param` получает допустимые значения (с учётом параметров, стоящих ДО него в порядке подбора)

#### 3.4 Построение ответа для каждого параметра

| Сценарий | `response_value` |
|----------|-----------------|
| Ошибка подбора | `None` |
| Управляется формулой | `None` |
| Выбран пользователем, ошибки нет | выбранное значение |
| После фильтрации осталось 1 значение | это значение |
| Параметр после ошибки в той же таблице | `None` (недоступен) |

`filtered_values` — допустимые варианты для параметра с учётом уже выбранных критериев.

#### 3.5 Формульный подбор

После табличного подбора вызывается `apply_new_and_legacy_formulas` — вычисляет формульные параметры на основе полученных значений.

## Ключевые функции

### `get_table_params_from_sql(table_name, table_params, selected_params, formula_driven)`
Выполняет SQL-запрос к конкретной таблице с фильтрацией по выбранным параметрам. Возвращает агрегированные уникальные значения и количество совпавших строк.

### `find_search_errors_multi_table(tables_map, selected_params, priority, formula_driven)`
Инкрементально ищет параметр-нарушитель в каждой таблице. Возвращает список ошибок с указанием таблицы, имени параметра и текста ошибки.

### `get_available_values_for_error_param(table_name, table_params, error_param_name, selected_params)`
Для ошибочного параметра получает допустимые значения, фильтруя по параметрам, стоящим до него в порядке подбора.

### `get_available_values_for_param(table_name, table_params, target_param_name, selected_params)`
Возвращает уникальные значения для параметра, учитывая все остальные выбранные критерии (кроме самого этого параметра).

### `get_ordered_table_params(table_params, priority)`
Сортирует параметры по полю `sort` (или `id`), при наличии `priority` — ставит его первым.

### `natural_sort_key(value)`
Ключ сортировки для естественного порядка: числа сортируются как числа, строки — как строки. «Нет», «nan», «» уходят в конец.

## Datamart (витрина данных)

Таблица `dm_product_{product_id}` — предвычисленные уникальные значения по всем параметрам без фильтрации. Пересоздаётся при изменении данных (флаг `is_dirty` в `datamart_registry`). Используется для начальной загрузки всех доступных значений без昂贵ных запросов к каждой таблице.
